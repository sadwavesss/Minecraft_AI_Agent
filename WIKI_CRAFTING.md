# Minecraft Crafting Recipes Wiki

## Описание

Функция просмотра рецептов крафтов Minecraft с использованием локальной базы данных и резервного LLM.

## Архитектура

### 1. **Локальная база данных** (`api/minecraft_recipes.py`)
- Содержит 25+ вручную проверенных рецептов крафтов
- Охватывает основные предметы: инструменты, оружие, броня, блоки
- Быстрый поиск (O(n)) с поддержкой частичного совпадения
- Каждый рецепт валидирован перед отправкой пользователю

### 2. **API эндпоинт** (`api/wiki.py`)
- `GET /api/wiki/craft?query={item}`
- Сначала ищет в локальной БД
- Если не найдено → использует LLM как резервный способ
- Возвращает JSON с валидированной 3x3 сеткой

### 3. **LLM интеграция** (`api/groq_client.py`)
- Метод `search_crafting_recipe_async(query)`
- Использует улучшенный промпт с инструкциями по формату
- Температура 0.0 для детерминированных результатов
- Валидирует результат перед возвратом

### 4. **Фронтенд** (`static/wiki.html` + `frontend/js/wiki.js`)
- Интерактивный интерфейс с Minecraft-стилизацией
- Поиск в реальном времени (по Enter)
- Отображение 3x3 сетки крафтинга
- Валидация данных на клиенте

- Факел, светильник

- [И ещё много...]

## Примеры использования

```
Запрос: "палка"
Результат:
  Название: Палка
  Описание: Основной материал для инструментов и оружия
  Сетка: [1x доска сверху, остальное пусто]

Запрос: "железный меч"
Результат:
  Название: Железный меч
  Описание: Эффективное оружие для боя
  Сетка: [железный слиток x2 вертикально, палка снизу]
```

## Поиск

- **Точное совпадение**: "палка" → найдёт "палка"
- **Частичное совпадение**: "железный" → найдёт "железную кирку", "железный меч" и т.д.
- **Регистронезависимый**: "ПАЛКА", "ПаЛкА" → найдут "палка"
- **Если не найдено в БД**: запрос отправляется в LLM (Groq/Ollama)

## Структура рецепта

```python
{
    "name": str,           # Название на русском
    "description": str,    # Описание и применение (1 строка)
    "grid": [              # Крафтинг сетка 3x3
        ["ингредиент", "ингредиент", "пусто"],
        ["ингредиент", "пусто", "пусто"],
        ["пусто", "пусто", "пусто"]
    ]
}
```

## Валидация

Все рецепты автоматически проверяются на:
- ✅ Правильный формат (dict с name, description, grid)
- ✅ Сетка ровно 3x3 (9 ячеек)
- ✅ Все элементы сетки - строки
- ✅ Пустые ячейки - "пусто"

## Исправления проблем

### Проблема 1: Не все крафты выдаёт
**Решение**: Добавлена локальная БД с 25+ рецептами. Если рецепта нет в БД - использует LLM.

### Проблема 2: Неправильное отображение
**Решение**: 
- Строгая валидация сетки (ровно 3x3)
- Проверка на клиенте перед отображением
- Улучшенные стили CSS для видимости

### Проблема 3: LLM галлюцинирует
**Решение**:
- Температура 0.0 для детерминированных ответов
- Более точный промпт с примерами
- Валидация структуры JSON

## Расширение БД

Чтобы добавить новый рецепт в `api/minecraft_recipes.py`:

```python
"название_предмета": {
    "name": "Название на русском",
    "description": "Краткое описание",
    "grid": [
        ["инградиент1", "инградиент2", "пусто"],
        ["инградиент3", "пусто", "пусто"],
        ["пусто", "пусто", "пусто"]
    ]
}
```

Затем запустите тест:
```bash
python test_recipes.py
```

## Тестирование

```bash
# Быстрый тест
python test_recipes.py

# Модульные тесты (требует pytest)
pytest tests/test_crafting_recipes.py -v
```

- Успешные поиски в БД
- Fallback на LLM
- Ошибки валидации

Смотрите `logs/` для подробной информации.
