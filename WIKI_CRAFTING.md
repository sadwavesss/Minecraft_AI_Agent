# Minecraft Crafting Recipes Wiki

## Описание

Функция просмотра рецептов крафтов Minecraft с использованием отдельной JSON-базы данных и резервного LLM.

## Архитектура

### 1. **JSON База данных** (`data/minecraft_crafting_recipes.json`)
- Отдельный файл с 27+ рецептами крафтов
- Простая структура для расширения
- Не требует перезагрузки кода при добавлении новых рецептов
- Каждый рецепт валидирован перед использованием

📖 **Документация**: `data/RECIPES_DATABASE.md`

### 2. **Загрузчик рецептов** (`api/minecraft_recipes.py`)
- Загружает и кэширует рецепты из JSON файла
- Предоставляет функции поиска и валидации
- Поддержка частичного и регистронезависимого поиска
- Автоматическая валидация всей базы

### 3. **API эндпоинт** (`api/wiki.py`)
- `GET /api/wiki/craft?query={item}`
- Сначала ищет в локальной БД
- Если не найдено → использует LLM как резервный способ
- Возвращает JSON с валидированной 3x3 сеткой
- Логирует все операции

### 4. **LLM интеграция** (`api/groq_client.py`)
- Метод `search_crafting_recipe_async(query)`
- Использует улучшенный промпт с инструкциями по формату
- Температура 0.0 для детерминированных результатов
- Валидирует результат перед возвратом

### 5. **Фронтенд** (`static/wiki.html` + `frontend/js/wiki.js`)
- Интерактивный интерфейс с Minecraft-стилизацией
- Поиск в реальном времени (по Enter)
- Отображение 3x3 сетки крафтинга
- Валидация данных на клиенте

### Декоративные
- Факел, светильник

## Примеры использования

```
Запрос: "палка"
Результат:
  Название: Палка
  Описание: Основной материал для инструментов и оружия
  Сетка: [1x доска сверху, остальное пусто]

Запрос: "железный меч"
Результат:
  Название: Железный меч
  Описание: Эффективное оружие для боя с мобами
  Сетка: [2x железный слиток вертикально, палка снизу]
```

## Поиск

- **Точное совпадение**: "палка" → найдёт "палка"
- **Частичное совпадение**: "железный" → найдёт "железный меч", "железный шлем" и т.д.
- **Регистронезависимый**: "ПАЛКА", "ПаЛкА" → найдут "палка"
- **Если не найдено в БД**: запрос отправляется в LLM (Groq/Ollama)

## Структура рецепта

```json
{
  "name": "Название на русском",
  "description": "Описание и применение (1 строка)",
  "grid": [
    ["ингредиент", "ингредиент", "пусто"],
    ["ингредиент", "пусто", "пусто"],
    ["пусто", "пусто", "пусто"]
  ]
}
```

## Валидация

Все рецепты автоматически проверяются на:
- ✅ Правильный формат (dict с name, description, grid)
- ✅ Сетка ровно 3x3 (9 ячеек)
- ✅ Все элементы сетки - строки
- ✅ Пустые ячейки - "пусто"

## Расширение БД

**Больше нет нужды менять Python код!**

Просто отредактируйте `data/minecraft_crafting_recipes.json`:

```json
"новый_предмет": {
  "name": "Название на русском",
  "description": "Краткое описание",
  "grid": [
    ["инградиент1", "инградиент2", "пусто"],
    ["инградиент3", "пусто", "пусто"],
    ["пусто", "пусто", "пусто"]
  ]
}
```

Затем запустите тест:
```bash
python test_recipes.py
```

## Исправления проблем

### Проблема 1: Не все крафты выдаёт
**Решение**: Отдельная JSON база с рецептами. Если рецепта нет в БД - использует LLM.

### Проблема 2: Неправильное отображение
**Решение**: 
- Строгая валидация сетки (ровно 3x3)
- Проверка на клиенте перед отображением
- Улучшенные стили CSS для видимости

### Проблема 3: LLM галлюцинирует
**Решение**:
- Температура 0.0 для детерминированных ответов
- Более точный промпт с примерами
- Валидация структуры JSON
- Локальная БД как первичный источник
