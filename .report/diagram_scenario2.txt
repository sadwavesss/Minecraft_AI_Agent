title Сценарий 2: Диалоговое взаимодействие (чат)

actor "Игрок" as Игрок
participant "Мод Minecraft" as Мод
participant "Сервер FastAPI\n(advice.py)" as Сервер
participant "Буфер событий\n(logs_db)" as Буфер
participant "LLM-клиент\n(GroqClient)" as Клиент
participant "Groq API /\nOllama" as LLM
participant "Веб-панель\n(браузер)" as Панель

== Нормальный поток ==

Игрок -> Мод : Ввод сообщения\nв игровой чат
Мод -> Мод : Перехват сообщения\n(обработчик чата)

Мод -> Сервер : POST /api/rp/chat\n{text: "текст сообщения"}

Сервер -> Буфер : Получить последние\n5 событий контекста
Буфер --> Сервер : [LogEntry × 5]

Сервер -> Клиент : generate_chat_response_async(\n  player_message,\n  recent_logs)

Клиент -> Клиент : Сформировать промпт\nиз шаблона chat_based:\n"{player_message}" + контекст

Клиент -> LLM : POST completions\n(модель, промпт,\nmax_tokens, temperature)
LLM --> Клиент : Текст ответа

Клиент -> Клиент : Удалить блоки\n<think>...</think>\n_strip_thinking()
Клиент -> Клиент : Форматировать ответ\n_format_rp_response()\nmax 100 символов
Клиент --> Сервер : Текст ответа

Сервер -> Сервер : Сформировать GroqAdvice\n{confidence: 0.9,\nsource: "chat"}
Сервер -> Сервер : Сохранить в историю\n_add_to_history(\n  response,\n  player_message)

Сервер -> Панель : WebSocket /api/rp/ws\n{response, source: "chat",\nplayer_message}
Сервер --> Мод : GroqAdvice\n{response, source: "chat"}

Мод -> Игрок : Отобразить ответ\nассистента (оверлей / чат)

== Альтернативный поток: пустое сообщение ==

Игрок -> Мод : Пустой ввод в чат
Мод -> Сервер : POST /api/rp/chat\n{text: ""}
Сервер -> Сервер : Проверка: text.strip() == ""
Сервер --> Мод : GroqAdvice\n{response: "...",\nconfidence: 0.0}

== Альтернативный поток: LLM недоступен ==

Сервер -> Клиент : generate_chat_response_async(...)
Клиент --> Сервер : None (ошибка / нет ключа)

Сервер -> Сервер : Сформировать\nрезервный ответ:\n"[RP] Интересное мнение,\nдруже!"
Сервер --> Мод : GroqAdvice\n{source: "fallback"}
Мод -> Игрок : Отобразить резервный ответ
